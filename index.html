    AppSec Discovery

    AppSec Discovery turns code into an inventory of the objects that carry data: database tables, API routes, gRPC methods, GraphQL operations, DTOs, Terraform resources. Every object has fields; rules mark the objects and fields that hold sensitive data (PII, payment, authentication secrets, ...):

    • keyword rules match names (last_name, card_number, a combination of fields),
    • LLM rules ask a model (any OpenAI-compatible API) with a prompt you write.

    Every rule match is a hit with a status: pending_review, match, no_match or need_more_info. In the service, LLM verdicts go through a tiered review: the service model categorises everything, a harness model (a capable model in an agent harness connected over MCP) checks what the service model was unsure about and a sample of what it was sure about, and a human decides the rest in the UI.

    There are two ways to use it:

    CLI / Python package appsec-discovery Service (appsec_discovery_service/)
    Input one source folder GitLab projects, polled over the API (main branches and open MRs)
    Rules conf.yaml edited in the UI / REST / MCP, stored in Postgres
    Output YAML / JSON / SARIF report inventory, hits and decisions in Postgres; UI, REST API, MCP server
    LLM optional, one endpoint the service model + optional harness model + human review
